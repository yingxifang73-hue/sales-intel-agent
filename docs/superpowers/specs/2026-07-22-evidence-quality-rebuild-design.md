# 客户调研证据质量重建设计

## 目标

让销售报告的内容密度来自可核验的公司、产品、动态和业务信号，而不是来源排序、搜索摘要或通用模板；在没有证据时简洁说明缺口。

## 已复现的问题

以 `honestypetfoods.com` 为例，实际流程采集到 16 条来源，但官网直连失败后，模型读取的前 8 条同时包含登录页、垃圾页面、Reddit 和通用竞品工具页面。搜索结果只保存短摘要，未继续抓取候选网页正文。严格引用校验因此正确拒绝了痛点、推荐理由和开场话术，最终报告只剩少量公司事实。

旧版报告的内容更多，是因为规则模板会把网页片段扩写成必填字段；这会让内容看似完整，但将未验证的推断包装为客户结论，不符合本产品的证据边界。

## 方案

### 1. 证据入库与身份门控

- 将官网直连、Firecrawl 官网抓取、搜索候选和扩展信息保留为不同采集来源。
- 对候选页面先进行目标公司身份校验：优先同域官网；外部页面必须同时具备可信域名、公司名称或品牌锚点，才可用于报告。
- 排除登录、后台、验证码、博彩、下载、社交讨论、通用工具页等低价值页面。
- 低于正文最小长度的搜索摘要不能直接作为报告证据，只能作为需要继续抓取的候选 URL。

### 2. 四类证据的正文扩展与排序

- 以公司、产品/服务、新闻动态、业务信号四类作为固定证据桶。
- 每桶优先选择官网正文；缺桶时才使用通过身份校验的外部公开页。
- 对每个候选 URL 抓取正文并清洗，再计算可读内容、类别、发布时间、目标公司匹配度和页面价值。
- 生成报告时按类别配额选择证据，而不是按采集顺序截取前 8 条。
- 竞品和公司扩展仅作为辅助桶，不能挤占公司、产品、动态和业务信号的核心证据位。

### 3. 报告合成

- 公司研究模型接收带短来源编号、类别、标题和正文摘录的证据包。
- 销售策略模型接收已验证的公司研究和对应证据，生成切入点、推荐理由、开场话术、待验证需求、发现型问题和下一步。
- 只有“文本 + 有效来源编号”同时通过检查的字段才展示。
- 如果某个类别没有通过校验的证据，报告显示一条简短缺口说明，不生成替代性的通用结论。
- 概览从已验证的公司研究中选择真实洞察，不使用采集阶段占位语。

### 4. 加载页

- 保留顶部产品品牌栏。
- 生成状态在可视区域正中，主标题缩小为单行“正在生成客户调研报告”。
- 只显示圆形进度、当前步骤和三段概览：采集公开资料、整理关键证据、生成销售准备；隐藏冗长说明与底部行业脚注。

## 成功标准

- 在同一案例中，报告模型输入不含登录、博彩、无关竞品工具和社交讨论页面。
- 模型输入至少按可用情况覆盖公司、产品、动态、业务信号中的多个类别，而不是只依赖首页和搜索摘要。
- 当来源不足时，报告不出现伪造的客户事实、痛点或产品效果。
- 当证据充分时，报告可展示公司画像、业务判断和销售准备中的多个可用字段。
- 加载页在常规浏览器缩放比例下居中、信息更少且不需要滚动查看进度。
