# 客户调研报告证据质量引擎设计

## 目标

将当前“原文片段填模板”的报告生成方式，重构为“资料清洗 → 证据筛选 → 中文理解 → 结构化报告 → 输出质检”。美的官网与“冰箱制造器”案例必须产出可读、相关、可追溯的中文售前报告。

## 已确认根因

1. 规则层直接截取英文来源前段并复用到多个章节，没有翻译和语义归类。
2. HTML 实体仅处理少量命名实体，没有处理 `&#39;`、`&quot;` 和数字实体。
3. Firecrawl 搜索结果未经过目标公司、页面类型、发布时间和章节相关性判断；子业务资料被当作集团整体结论。
4. 模型只生成痛点和话术，公司概览与公司分析仍使用原始英文片段。
5. 产品描述被自动补成调研 Agent 的价值，而不是销售人员输入的产品含义。
6. 既有测试只验证字段数量和 API 成功，没有验证语言、乱码、相关性和销售可用性。

## 新数据流

### 1. 来源清洗

- 解码命名、十进制和十六进制 HTML 实体。
- 清除 Markdown 链接语法、重复导航、Cookie、版权和无意义按钮文案。
- 保留来源 URL、标题、来源类型、发布日期和规范化文本。

### 2. 证据选择

- 官网来源优先用于公司介绍、产品和业务覆盖。
- 只有带明确新闻语义、日期或公告标题的来源才进入“近期动态”。
- 外部来源必须包含目标公司品牌或目标域名；无法确认主体的来源不进入报告。
- 子品牌或业务部门资料必须在结论中明确其范围，不得自动推广为集团整体事实。
- 每个来源选择若干高信息密度段落，而不是机械截取前 520 个字符。

### 3. 中文结构化研究

- DeepSeek 负责整份 Company Overview 和 Company Analysis 的中文理解、翻译与归类，而不仅是销售话术。
- 所有事实字段必须返回有效 `sourceIds`；证据不足时明确写“当前公开资料不足”，不得补造。
- 研究提示词明确区分目标公司整体、子业务、新闻和推断。

### 4. 产品关联与销售策略

- “你的产品”输入框允许输入产品名称或一条自然语言描述，不增加新的价值主张字段。
- 不再自动把调研 Agent 的价值写入销售方产品。
- 若产品信息仅有名称，允许生成谨慎的关联假设，但必须标注待验证，不得编造功能或指标。
- 销售建议必须同时引用目标公司的公开信号和用户输入的产品；否则不得显示为推荐理由。

### 5. 输出质量门

报告交付前必须通过：

- 中文可读性：除品牌名、产品名和必要专有名词外，正文以中文为主。
- 编码完整性：不得包含未解码 HTML 实体或明显乱码。
- 引用完整性：所有公开事实必须关联存在的来源 ID。
- 章节相关性：近期动态不得用普通产品介绍代替；子业务不得冒充集团结论。
- 销售相关性：销售策略包含用户产品名和至少一条客户公开信号。
- 重复控制：同一原文不得原样重复填充多个章节。

任一模型结果未通过质量门时，系统不展示有问题的原文；保留来源并明确提示“中文研究未完成，请重试”，避免交付看似完整但不可用的报告。

## 模型调用策略

采用两阶段调用以降低单次 JSON 截断风险：

1. **公司研究调用**：输出公司概览、产品服务、行业覆盖、近期动态、商业模式、产品定位、目标客户、竞争观察和痛点假设。
2. **销售策略调用**：基于第一阶段研究结论和“你的产品”生成切入点、推荐理由、开场话术、待验证需求、问题和下一步。

两个阶段分别宽松解析、字段归一化和质量校验。公司研究失败时不得继续伪造销售策略。

## 美的案例验收

输入：

- 官网：`https://www.midea.com/global`
- 行业：制造业
- 你的产品：冰箱制造器

必须满足：

1. 公司介绍、产品服务、行业覆盖和公司分析为中文。
2. 不包含 `&#39;` 等 HTML 实体。
3. “Midea Robotics and Automation”如被引用，明确说明是美的集团相关业务板块，不作为美的家电品牌整体定位。
4. 近期动态来自新闻/公告语义内容，不用普通业务介绍充当动态。
5. 销售建议明确提到“冰箱制造器”，并将其表述为待验证的产品关联，不编造具体能力。
6. 每项事实可从来源链接核验。
