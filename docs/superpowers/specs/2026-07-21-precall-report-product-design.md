# Pre-call Research Report 产品设计

## 产品承诺

销售只需要输入客户官网、行业预设和自己的产品信息，即可获得一份用于首次电话或拜访前准备的 B2B 客户调研报告。它替代“搜索多个网页、做笔记、再想销售话术”的重复工作，但不把公开信息推断成客户已确认的内部事实。

## 输入

- **目标公司官网**：唯一必填的公开资料入口。
- **行业预设**：通用、电商、外贸、AI、制造业；影响研究关键词和发现型问题。
- **你的产品**与**一句价值主张**：用于将调研结论转译为销售切入建议。

LinkedIn、新闻和公众号链接不作为第一版输入项；Firecrawl 的公开搜索用于补充可用网页和新闻。

## 采集与生成

1. Node.js 直连官网，收集公司介绍、产品/服务、页面中的客户/市场信息、新闻或动态线索。
2. Firecrawl 始终作为第二步补充官网 Markdown 与公开网页/新闻。
3. 来源去重、提取可读摘要，并按来源类型和内容分配给报告各章节。
4. 证据生成层先产出完整报告；模型增强再补充分析、痛点假设、沟通建议和话术。模型未采用时，完整报告仍可基于真实来源交付。

## 报告结构

### 1. Company Overview｜公司概览

- 公司介绍
- 产品和服务
- 所属行业与业务覆盖
- 近期动态
- 每项内容都有来源编号

### 2. Company Analysis｜公司分析

- 商业模式
- 产品定位
- 目标客户
- 竞争情况或竞争观察
- 业务核心潜在痛点（全部标注“待验证”，并关联公开信号）

当公开证据不足以支持竞争结论时，明确写“当前公开资料不足，建议沟通中验证”，不编造竞争对手或客户信息。

### 3. Sales Strategy｜销售策略

- 电话/拜访切入点
- 推荐理由：用户产品如何对接观察到的公开信号
- 可直接使用的开场话术
- 可能的潜在需求（待验证）
- 第一次电话的 5 个发现型问题
- 建议下一步和沟通边界

### 4. Sources｜来源与采集状态

- 分组显示官网、公开新闻/网页来源。
- 显示直连、Firecrawl、模型采用状态；成功状态不显示为错误。

## UI 设计

保留当前蓝色、白色、细网格的瑞士风格，但从“4 格卡片”改成纵向报告：

- 报告顶部展示公司域名、行业预设、资料来源数量和生成状态。
- 四个章节使用清晰的编号、标题和留白；摘要/事实、待验证假设、销售动作使用不同的轻量视觉层级。
- 关键销售内容（切入点、开场话术、发现型问题）使用可扫读的突出区块。
- 来源置于报告底部并保留可点击链接。

## 验收标准

1. 保留官网、行业预设、产品和价值主张四项输入信息。
2. 每次生成完整输出四个报告章节，不再只显示简略作战卡。
3. 公司概览至少包含公司介绍、产品/服务、行业/覆盖和近期动态；没有证据的项明确说明资料不足。
4. 公司分析包含商业模式、产品定位、目标客户、竞争观察和带证据的待验证痛点。
5. 销售策略包含切入点、推荐理由、开场话术、潜在需求、5 个发现型问题和下一步。
6. 报告中的公开事实与来源可追溯；推断内容标注待验证。
7. 真实官网端到端请求能返回完整结构；模型未采用时仍返回完整证据版报告。
