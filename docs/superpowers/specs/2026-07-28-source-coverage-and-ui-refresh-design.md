# 来源覆盖与 UI 更新设计

## 目标

让每次调研以真实、可追溯的公开资料优先补齐公司介绍、规模与能力、客户或合作事实；同时把当前产品界面改为桌面 `UI设计图/01.png` 至 `04.png` 的视觉与信息层级。

## 数据采集

1. Firecrawl 继续作为官网正文采集器，但页面选择不再只依赖 URL 中的英文/中文关键词。首页、站点地图链接、页面标题和正文中的导航语义共同评分；每个“公司、产品、新闻、业务信号”类别最多选取若干高分页面。
2. Serper 继续作为外部公开资料发现器。先由官网标题、结构化数据、品牌页文字、域名和搜索候选交叉建立公司身份（中文名、英文名、品牌别名），再用已确认的身份查询公司介绍、规模能力、客户/合作、新闻与行业信号。
3. 每个关键字段有独立的覆盖判定。公司介绍、规模能力、客户事实任一不足时，使用已确认名称进行一次定向补搜和正文抓取；搜索摘要不能替代深度页面正文。
4. 模型只将采集到的来源正文转换为结构化字段；没有来源的结论保持“信息不足/待验证”，不使用模型常识补写。客户事实仅接受来源直接描述的客户、合作伙伴、案例或渠道事实。
5. 采集诊断保留在报告内部质量审计中，但不增加前端证据抽屉。

## 界面与交互

- 保留两个主入口：`调研输入`、`历史报告`。
- 输入、进度、报告页分别对齐 `01.png`、`02.png`、`04.png`；联系方式部分对齐 `03.png`。
- 页面使用白底、黑色主操作按钮、灰色细边框、无装饰性渐变。导出按钮始终为同一种黑色主按钮。
- 报告页保留销售结论、联系方式与地址、客户画像、产品匹配、机会痛点、沟通方案、下一步、补充信息的既定内容范围。第 7 部分默认折叠。
- 移除“查看证据”、证据抽屉、来源侧栏、原始 JSON 前端入口以及相关回调；来源仍在报告数据中保存，供导出与审计使用。
- `导出报告` 生成 PDF，而不是 JSON。PDF 使用浏览器打印布局，包含报告正文而不包含应用导航。

## 边界与失败行为

- 不新增独立前端项目，不改变用户输入字段，不使用假数据填充空状态。
- Firecrawl、搜索、正文抓取和模型整理均维持超时与独立失败降级；单一渠道失败不能抹掉其他渠道结果。
- 搜索 API 未配置或失败时，明确保留官网采集结果与信息缺口；不会把缺口伪装成已验证事实。
