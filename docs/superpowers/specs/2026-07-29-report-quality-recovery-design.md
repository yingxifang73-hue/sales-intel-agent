# 销售调研报告质量恢复设计

## 目标

修复当前“采集内容充足，但最终报告短、杂、空”的数据链路问题。保留现有 Next.js 前端、Supabase 任务状态、Vercel Workflow 异步执行和既定报告栏目，不创建重复项目，也不依赖固定公司数据。

## 已确认根因

1. SHOPLINE 任务采集 64 个来源、选择 20 个来源，但 14 个逐来源模型请求超时。
2. 来源选择把招聘站、搜索摘要和帮助中心页面排在核心官网正文之前。
3. 搜索摘要被当作正式事实写入报告，短摘要和导航文本污染客户画像。
4. 逐来源模型请求没有真正重试；模型超时后，本地关键词降级把页面导航、营销口号误判为完整事实。
5. 机会分析和沟通方案模型阶段失败后，系统仍保存降级内容并把任务标记为完成。
6. 最终质量审计为未达标时，工作流仍然结算次数并交付报告。
7. 线上加载页仍可显示旧文案，缺少针对最终生产资源的文案验证。

## 数据流

1. 采集层保留官网、Firecrawl 正文、Jina 正文和外部搜索结果。
2. 搜索摘要只用于发现待抓取 URL；未取得正文的摘要不能进入报告来源。
3. 来源筛选先保证官网核心页、产品/服务页、关于页、联系页、客户案例和可信新闻，再补充其他来源。
4. 每个入选来源独立提取结构化事实。模型调用使用有界并发、重试和退避；失败时只保留保守且可验证的正文句子。
5. 跨来源事实按公司概况、产品服务、客户市场、商业模式、定位能力、近期动态、联系方式和业务信号合并；不再简单取第一个字段。
6. 基于合并后的事实库分别生成产品匹配、机会与痛点、首次沟通方案。
7. 质量闸门检查核心阶段、核心栏目、文本质量和来源覆盖。未通过时执行一次定向修复；仍未通过则任务失败并释放试用次数，不能作为正式报告交付。

## 内容标准

- 客户画像至少覆盖公司概况、产品与服务、目标客户/市场、商业模式、定位、规模能力和近期动态中的五项。
- 产品匹配必须说明目标公司场景、我方能力、适配点、限制条件和需确认事项。
- 机会与痛点至少形成两条结构化机会；每条包含公开信号、潜在痛点、业务影响、产品匹配和沟通问题。没有直接采购证据时必须标记为分析判断，不能伪装成事实。
- 首次沟通方案至少包含联系角色、沟通目标、开场话术、价值桥接、三条发现问题、异议应对、材料准备和下一步。
- 中文报告不得直接展示搜索摘要标签、导航堆叠、无意义英文口号或“等待模型生成”占位文案。
- 电话、邮箱、地址只从公开正文确定性提取；找不到时不编造。

## 加载页

主标题与说明统一为：

- 主标题：正在生成销售调研报告
- 说明：调研需要一定时间，保证数据准确性，请耐心等待~

工作流具体阶段信息只显示在进度区域，不覆盖上述说明。生产部署后必须直接检查线上 JavaScript/HTML 资源包含新文案。

## 验收

- 自动化用例证明搜索摘要不会成为正式报告来源。
- 自动化用例证明招聘页不会覆盖官网公司概况。
- 自动化用例证明模型首次超时会重试，单来源失败不会清空其他事实。
- 自动化用例证明机会/沟通阶段失败或最低质量未达标时任务不会标记 completed。
- 自动化用例证明核心栏目具有最低结构和内容量。
- 类型检查、单元测试、生产构建通过。
- 不运行真实公司调研，不消耗兑换码；只部署已通过自动化验证的版本。
