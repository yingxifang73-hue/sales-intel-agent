# 销售调研 Agent 精简 UI 设计

日期：2026-07-28

## 目标

在不丢失完整调研内容的前提下，让销售人员先看结论、机会、联系方式和下一步，再按需阅读完整分析。UI 保持 Notion 风格，不照搬现有 14 张设计图中的重复页面、空表格和未实现功能。

## 页面范围

产品只保留四类页面或状态：

1. 调研输入
2. 研究进度
3. 历史报告
4. 完整报告

报告内容不拆成多个独立页面。完整报告采用固定章节目录加中央连续长页，章节顺序为：

1. 销售结论与联系方式
2. 客户画像
3. 产品匹配判断
4. 机会与痛点
5. 首次沟通方案
6. 下一步建议
7. 补充信息与证据备份

第七部分默认折叠，只作为附录和追溯入口。

## 视觉方向

- 以现有 UI 设计图 `03.png` 为报告页视觉母版。
- 使用白色或暖白背景、黑色和中性灰文字、浅灰细边框。
- 保留大量留白和清晰的文档层级。
- 少量低饱和蓝色、绿色和橙色只用于状态提示。
- 不使用渐变、玻璃拟态、数据大屏、密集阴影或大面积彩色卡片。
- 不将每一句话放进独立卡片。
- 左侧主导航只保留“调研输入”和“历史报告”。

## 调研输入页

必填字段只有：

- 目标公司官网
- 行业
- 我方产品名称

“补充产品信息”默认折叠，展开后可填写：

- 价值主张
- 目标客户
- 客户常见痛点
- 证明材料、认证或客户案例
- 建议下一步

公司名称、地址、规模、联系方式等信息由系统研究获得，不要求用户预先填写。

## 研究进度页

进度必须对应现有真实事件，只显示六个阶段：

1. 验证目标网址
2. 采集官网与外部公开信息
3. 提取客户事实
4. 分析产品匹配与机会
5. 生成首次沟通方案
6. 校验事实与最低交付标准

阶段状态包括：等待中、进行中、已完成、部分完成、失败。警告不阻断能够继续完成的研究；失败步骤提供重试或返回输入入口。

## 完整报告页

### 第一屏

第一屏必须在无需滚动过多的情况下回答：

- 是否值得联系
- 为什么值得联系
- 最优机会是什么
- 建议联系谁
- 如何联系
- 下一步做什么

第一屏包含：

- 销售结论
- 联系建议
- 产品匹配程度
- 机会置信度
- 数据完整度
- 三个以内的关键客户信号
- 一个优先机会
- 推荐联系角色
- 已获得的电话、邮箱、官网、线上入口和地址
- 一个明确的下一步行动

### 后续章节

中央区域按章节连续向下阅读。左侧目录固定，点击后滚动到对应章节。长内容默认摘要，用户可以选择“查看全部”。

## 联系方式与地址

联系方式是报告的高优先级模块，但不使用大面积空表格。

展示顺序：

1. 已验证电话和邮箱
2. 官网及官网联系页面
3. 已验证线上渠道
4. 已验证线下地址
5. 真实公开联系人
6. 推荐联系角色

规则：

- 只突出真实获取到的数据。
- 电话、邮箱或地址未获取时，合并成一条简短说明。
- 没有真实联系人时，不渲染空联系人列表。
- “真实公开联系人”和“建议联系角色”必须分开。
- 不允许虚构姓名、职位、电话、邮箱和地址。
- 每条已获取信息保留验证状态和来源入口，但来源详情默认进入抽屉。

## 动态内容与空状态

- 零条数据的卡片不渲染。
- 同类缺失信息集中提示一次，不重复显示多行“未获取”。
- 关键客户信号首屏最多三条。
- 机会优先展示一条，完整章节最多三条。
- 产品和近期动态根据真实数组长度自动排版。
- 内容较少时缩短页面，不通过空卡片填满画布。
- 内容较多时使用摘要、展开和章节跳转，不裁掉真实信息。

## 明确不做

- 模板管理
- 客户列表
- 我的资料
- 设置
- CRM 任务负责人
- 任务完成状态
- 虚构销售人员姓名
- 虚构采购负责人
- 将证据备份拆成多个重复页面
- 为填满页面生成假数据

## 数据映射

UI 使用现有 `SalesReport` 和 `ReportViewModel`，不得创造后端不存在的核心业务字段。

- 销售结论：`verdict`
- 客户画像：`intelligence`
- 产品匹配与机会：`opportunity`
- 首次沟通与下一步：`conversation`
- 证据与风险：`evidence`
- 数据完整度：`quality`

所有字段依据状态显示为已核验事实、AI 判断、待验证、信息不足或冲突风险。

## 验收标准

- 销售人员在报告第一屏能够理解是否值得联系、联系谁、为什么以及下一步。
- 完整报告六个主要章节均有固定位置，但没有数据时不会出现大面积空白。
- 联系方式模块不虚构数据，并能区分真实联系人和建议角色。
- 所有真实报告字段都有展示路径。
- 证据备份默认不干扰主阅读流程，但仍可追溯。
- 页面与当前真实六阶段研究流程一致。
- 不新增当前项目没有的 CRM 或模板功能。
