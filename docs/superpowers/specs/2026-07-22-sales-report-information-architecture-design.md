# 销售调研报告完整信息架构设计

## 目标

把一次完整调研结果组织为销售人员能直接使用的五层报告，保证所有通过质量校验的字段都有明确展示位置，同时避免把爬虫原文和技术字段堆进正文。

## 视觉方向

采用 Swiss 信息设计：白色和冷灰表面、深墨绿单一强调色、左对齐排版、清晰网格与 1px 分隔线。页面的识别动作是“证据就地可追溯”：所有事实、信号、判断和假设旁边都有可点击的来源编号。

## 全局报告头

固定展示客户名称、官网、行业预设、调研时间、来源数量和耗时；同时展示本次销售方产品名称、价值主张、目标客户、客户常见问题、证明材料和期望下一步。历史记录必须保存完整 `sellerProfile`，旧记录允许仅有 `productName`。

## 五个模块

### 01 调研速览

一屏回答是否值得联系：本次联系结论、客户业务、关键变化、产品匹配、首要待验证机会、建议下一步和前三条关键公开信号。此页只做摘要，详细内容链接到后续模块。

### 02 客户事实

完整展示公司介绍、产品与服务、行业与业务覆盖、商业模式、产品定位、目标客户、近期动态和公司研究信息缺口。事实必须带来源，缺失字段不显示空卡片。

### 03 机会与匹配

展示业务信号、全部痛点假设、业务影响、置信度、验证问题、潜在需求、全部产品能力匹配、竞争观察、风险与分析边界。推断统一标记“待验证”。

### 04 首次沟通

展示沟通目标、全部切入点、推荐理由、价值桥接、可直接使用的开场话术、最多五个发现型问题及其目的、可用证明材料、建议下一步、沟通禁区和策略说明。

### 05 证据与边界

展示证据覆盖摘要、最多三十条证据主张及其原文片段/状态/类别、按类型分组的正式来源、采集说明、警告、模型状态和调研指标。原始整页正文、哈希和内部 ID 只进入折叠技术详情，不进入销售正文。

## 字段优先级与去重

- 痛点：`companyAnalysis.painHypotheses`，缺失时使用顶层 `painHypotheses`。
- 开场：`salesStrategy.opening` → `talkTrack.opening` → 顶层 `opening`。
- 问题：`salesStrategy.discoveryQuestions` → 顶层 `questions` → `talkTrack.discoveryQuestions`。
- 下一步：`salesStrategy.recommendedNextStep` → `talkTrack.recommendedNextStep` → 卖方 `callToAction`。
- 禁区：`salesStrategy.avoid` → `talkTrack.avoid`。
- 产品匹配、切入点、潜在需求等数组必须全部渲染，不能只取第一条。
- 摘要允许引用详细内容，但同一详细字段只在一个主模块完整展示。

## 空态与证据规则

- 没有事实证据时显示“未找到可核验信息”，不生成通用占位建议。
- 每个带 `sourceIds` 的字段显示来源按钮。
- `verified`、`insufficient`、`conflicting` 使用不同状态标签。
- 信息缺口可以没有来源，但必须明确写成信息缺口，不能伪装为事实。

## 布局和字号

- 桌面内容宽度 1180–1240px，移动端单列。
- 报告标题 30–34px，模块标题 22–24px，卡片标题 16–18px，正文 15–16px、行高 1.75，来源信息 12–13px。
- 01 使用结论横幅、四张判断卡和 7/5 双栏；02 使用事实卡与全宽时间线；03 使用纵向痛点卡和匹配矩阵；04 使用全宽开场话术与编号问题清单；05 使用证据状态筛选、来源列表和折叠说明。

## 验收标准

- 完整测试报告中的每个字段至少在一个模块出现。
- 所有数组项目都能展示，所有备用字段都能正确兜底。
- 历史报告恢复后仍保留完整卖方产品背景。
- 1920px、1366px 和移动端无大片无意义留白，正文不需要缩放到 80% 才能阅读。
- 所有事实和判断均可追溯来源，证据不足与信息冲突不会显示成已确认事实。
