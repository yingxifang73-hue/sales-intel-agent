# 客户调研质量与加载状态设计

## 目标

让 B2B 销售在输入官网和产品信息后，得到一份信息充分、可追溯、可用于首次沟通的中文调研报告；当公开信息不足时保留模型的可读总结，并清楚标为待验证，而不是整块删除。

## 已定位的问题

同一官网的真实运行中，直连采集失败后，系统把 Firecrawl 搜索摘要、登录页、垃圾页面和竞品搜索结果混在来源前列；模型只读取前 8 条来源，因而没有看到足够的公司、产品、新闻和业务信号正文。严格来源 ID 校验随后删除了模型中可读但引用格式不完整的字段，导致报告显得很少。

## 方案选择

采用“证据质量优先、模型总结不丢弃”的两层方案：先让采集层提供可信、按类别均衡的正文证据；再让模型以短来源编号生成完整中文报告。引用格式不完整时不再删除整段内容，而是保留文字并标记为“待验证”；明确无关、垃圾或身份不匹配的页面在进入模型前删除。

不采用旧版的模板填充方案：它会让报告看起来很长，但会把通用推测伪装成目标客户事实。

## 数据流

1. 直连官网抓首页和分类内页，先提取公司身份线索。
2. Firecrawl 仅补足缺少的公司、产品、新闻、业务信号类别；搜索结果链接需要抓取正文，不能直接把摘要交给模型。
3. 对每条来源评分：目标公司身份、同域/权威域、页面类别、正文长度、垃圾风险、重复度。
4. 按四类证据桶各选高分来源，形成平衡的模型上下文；竞品和企业信息仅在已确认目标公司身份后进入对应模块。
5. 模型生成公司画像、业务判断、销售准备和摘要。每条输出带短来源编号；编号无法解析时，保留内容并在 UI 显示“待验证”。
6. 页面展示真实内容、来源和验证状态；不使用通用占位段落替代缺失结论。

## 报告内容标准

- 公司画像：公司介绍、产品/服务、行业与业务覆盖、近期动态。
- 业务判断：商业模式、产品定位、目标客户、竞争观察、业务核心潜在痛点。
- 销售准备：切入点、推荐理由、可直接使用的开场话术、待验证需求、5 个发现型问题、下一步建议。
- 每一项结论显示“已引用”或“待验证”；后者是需要销售确认的假设，不是已证实事实。

## 加载页

加载状态使用单一居中面板：小标题“正在调研”、当前步骤、圆形进度和三个阶段（采集、分析、生成）。去掉大标题、长副标题、冗余步骤列表和底部说明，使 100% 缩放下完整可见。

## 验收标准

- 同一案例中，模型上下文不含登录页、博彩垃圾页或明显无关的竞品页面。
- 进入模型的来源覆盖至少公司、产品/服务、业务信号中的两类；否则报告明确显示证据缺口。
- 报告在有有效公开内容时输出完整模块，销售准备至少显示 5 个问题和下一步建议。
- 对引用格式不完整但文字可读的模型结论，报告保留文字并标记“待验证”。
- 加载页的核心面板在常用 100% 缩放下居中、完整可见。
