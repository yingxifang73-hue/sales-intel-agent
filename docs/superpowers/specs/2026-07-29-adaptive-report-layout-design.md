# 报告卡片自适应与长文本无损分段设计

## 目标

解决报告详情页的两个纯展示问题：

1. 联系方式卡片只有少量内容时仍被同一行的高卡片拉伸，产生大面积空白。
2. 产品与服务等模块出现超长文本时整段连续展示，阅读困难。

本次只修改展示层，不改变采集、分析、报告 Schema 或已生成的报告内容。

## 视觉方向

继续沿用当前 Notion 风格：白色表面、浅灰边框、克制圆角和清晰信息层级。卡片高度由真实内容决定，不通过固定高度制造版面体量。

## 卡片自适应

- 联系方式卡片网格使用顶部对齐，不允许同一行卡片相互拉伸。
- 删除联系卡片的固定最小高度。
- 有一条入口时，卡片仅保留标题、该条入口和正常内边距。
- 多条联系方式仍按现有行样式自然向下增长。
- 移动端继续保持单列布局。

## 长文本无损分段

- 新增独立的展示函数，只负责把长文本切分为可读段落。
- 仅当文本超过长度阈值时启用分段；短文本保持当前展示。
- 优先在原文已有的句号、分号、问号、感叹号等边界处分段。
- 若单句极长，再在原文已有的逗号边界处分段。
- 每一个标点仍保留在原位置，不删除、替换或新增业务文字。
- 视觉项目符号由 CSS 绘制，不写入报告原文。
- 所有分段按原顺序展示；把各段直接拼接后必须与输入原文逐字相等。

## 组件边界

- `ContactSection` 保持数据处理不变，卡片问题由 CSS 修复。
- 新增一个可复用的无损分段展示组件，输入只接收原始字符串和阈值。
- `TabBusinessProducts` 的产品与服务列表接入该组件。
- 其他已经使用折叠/摘要展示的模块暂不改变，避免扩大本次范围。

## 验收标准

- 单条“优先联系入口”卡片不再与旁边高卡片等高。
- 长产品信息能够按标点分成多个清晰条目。
- 分段前后除换行和视觉项目符号外，原始文字逐字一致。
- 不改变报告中的内容、顺序、来源和字段结构。
- 桌面端和移动端均不出现内容溢出。

## 测试

- 单元测试验证分段结果重新拼接后严格等于原文。
- 单元测试验证短文本不分段。
- UI 测试验证长文本生成多个展示段落。
- 运行完整测试、类型检查和生产构建。
